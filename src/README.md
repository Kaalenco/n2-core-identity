# N2.Core.Identity — Developer Guide

This document explains how to build, test, and maintain the project locally and in CI.

## Solution Structure

```
src/
├── N2.Core.Identity/               # Main library (multi-targeted: net10.0, net11.0)
├── N2.Core.Identity.UnitTests/     # Unit and integration tests (MSTest)
├── Directory.Build.props           # Shared build settings (warnings as errors, analyzers)
└── N2.Core.Identity.sln
```

## Building

```bash
# Restore dependencies
dotnet restore src

# Build (Debug, all targets)
dotnet build src --no-restore

# Build (Release — also produces the .nupkg)
dotnet build src --no-restore --configuration Release
```

> `GeneratePackageOnBuild` is enabled, so a `.nupkg` is created automatically on Release builds.

## Running Tests

### Unit tests (excludes integration tests)

```bash
dotnet test src --no-build --verbosity normal --filter "TestCategory!=Integration"
```

### All tests including integration (requires a running SQL Server instance)

```bash
dotnet test src --no-build --verbosity normal
```

### Single test by name

```bash
dotnet test src --filter "FullyQualifiedName=N2.Core.Identity.UnitTests.N2UserManagerTests.TestUserCreateAsync"
```

Test results (`.trx` files) are written to `src/TestResults/`.

## MySQL

MySQL support (Pomelo provider, MySQL integration tests and the Docker Compose test
environment) was removed in 2.0.0: no stable EF Core 10 MySQL provider from Pomelo exists yet.
It is planned to return as a separate package, N2.Core.Identity.MySql.

## CI/CD Pipeline

### Build, test and publish (`.github/workflows/dotnet.yml`)

Runs on push and PR to `trunk`. Steps: authenticate to the private `vault-packages` feed,
restore, Release build (produces the `.nupkg` through `GeneratePackageOnBuild`), unit tests
(`TestCategory!=Integration`), and on pushes to `trunk` only: `dotnet nuget push` to
`vault-packages` with `--skip-duplicate`, so only a version bump publishes a new package.
nuget.org is handled by n2-publishing from the feed, not by this workflow.

`N2.*` packages come from `vault-packages` (see `src/nuget.config`, no credentials in the
file). The repository secret `NUGET_PAT` (Packaging read and write) is added to the runner's
copy of `src/nuget.config` only. For local restore use the Azure Artifacts Credential Provider.

### CodeQL security scanning (`.github/workflows/codeql.yml`)

Runs GitHub's CodeQL static analysis on pushes and PRs to `trunk`, and on a weekly schedule
(Wednesdays at 09:38 UTC). Scans both C# source code and the GitHub Actions workflow files
for security vulnerabilities. Results appear in the repository's **Security → Code scanning**
tab.

> **This is an externally maintained workflow**, generated by GitHub. Periodically check for
> an updated version at `github.com/github/codeql-action` releases and regenerate or update
> the file accordingly — particularly when new CodeQL action major versions are released
> (currently `github/codeql-action/init@v4` and `github/codeql-action/analyze@v4`).

## Regular Maintenance

### GitHub Actions versions

The workflow pins specific versions of community actions. Periodically check for updates using
the GitHub CLI:

```bash
gh release list --repo actions/checkout --limit 5
gh release list --repo actions/upload-artifact --limit 5
```

Always review the changelog for breaking changes before bumping a major version.
Current versions in use are documented in a comment at the top of the workflow file.

### .NET SDK targets

The library targets `net10.0` and `net11.0`. When a .NET version reaches end-of-life, remove
its `<TargetFramework>` entry from `N2.Core.Identity.csproj` and the corresponding
`<PackageReference>` condition block, then update the workflow's `Setup .NET` steps accordingly.

### NuGet package version

The package version is set manually in `N2.Core.Identity.csproj`:

```xml
<Version>3.0.1</Version>
<PackageVersion>3.0.1</PackageVersion>
<AssemblyVersion>3.0.0.0</AssemblyVersion>
<FileVersion>3.0.1.0</FileVersion>
<ProductVersion>3.0.1</ProductVersion>
```

Bump the version values together (AssemblyVersion only on a major bump) before merging a release to `trunk`.

### NuGet dependencies

Dependency versions are declared in `N2.Core.Identity.csproj`.
Both targets share one dependency set (EF Core and ASP.NET Core on the 10.0.x band). Update
them when security advisories are published for any of the referenced packages.
