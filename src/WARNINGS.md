# Suppressed warnings

This document explains each warning suppressed via `<NoWarn>` in the project files or
`#pragma warning disable` in source files.

Because this library wraps ASP.NET Core Identity and Entity Framework Core, several analyser
rules that conflict with framework conventions, DI patterns, or design-time tooling requirements
are intentionally silenced.

| Warning | Analyser | Name | Reason for suppression | Severity | Safe to ignore when |
|---------|----------|------|------------------------|----------|---------------------|
| `CA1031` | Roslyn / CA | Do not catch general exception types | Several operations interact with external systems (database health checks, token parsing, MFA encryption) where the set of possible exceptions spans many unrelated types. Each catch block returns a safe fallback (null or false) without swallowing actionable errors. | Low | The catch block performs no side effects beyond returning a safe fallback value. Re-enable if any site begins branching on exception type. |
| `CA1515` | Roslyn / CA | Consider making public types internal | MSTest requires public test classes for the test runner to discover them. Applying `internal` breaks discovery. | Designer choice | Applied to test projects only. Do not suppress in production assemblies. |
| `CA1707` | Roslyn / CA | Identifiers should not contain underscores | Test methods follow the `Method_Condition_Expected` naming convention for readability. The underscores are intentional and meaningful. | Designer choice | Applied exclusively to test method identifiers. Do not suppress in public API or production types. |
| `CA1725` | Roslyn / CA | Parameter names in member overrides should match the name in the base | CancellationToken parameters are named `ct` throughout this library rather than `token` (the ASP.NET Core base-class name) to avoid shadowing JWT token variables in the same scope. | Designer choice | Safe as long as no caller passes a CancellationToken by the base-class parameter name using named-argument syntax. |
| `CA1812` | Roslyn / CA | Avoid uninstantiated internal classes | Internal classes are instantiated by the DI container or EF Core design-time tooling via reflection. The analyser cannot detect reflection-based activation. | Low | The class is only ever resolved via DI, EF design-time services, or a factory. Re-enable if the class gains a direct constructor call site. |
| `CA1819` | Roslyn / CA | Properties should not return arrays | Array-returning properties appear on internal data classes where immutability is enforced by convention; no caller modifies the returned array. | Low | The property is on an internal or read-only data class not exposed on a mutable public API. |
| `CA1848` | Roslyn / CA | Use the LoggerMessage delegates | Used in a legacy plaintext passthrough path that executes infrequently during secret migration. The performance overhead is negligible on this path. | Low | The logging call is on an infrequent code path. Add a `LoggerMessage` delegate if the path becomes hot. |
| `CA1859` | Roslyn / CA | Use concrete types when possible for improved performance | Test code uses interface types intentionally to stay consistent with the DI contracts used in production. Switching to concrete types would diverge the test surface from the actual usage pattern. | Designer choice | Applied to test classes only. |
| `CA1862` | Roslyn / CA | Use the StringComparison method overloads | Used inside EF Core LINQ queries translated to SQL. The database engine handles case sensitivity; the StringComparison overload produces an identical query. | Low | The query always executes against a database backend. Re-evaluate if in-memory LINQ evaluation is introduced. |
| `CA2007` | Roslyn / CA | Do not directly await a Task without calling ConfigureAwait | This library targets ASP.NET Core, which has no SynchronizationContext. `ConfigureAwait(false)` would be a no-op and is omitted to reduce noise. | Low | The library is consumed only by ASP.NET Core applications. Re-evaluate if referenced from WPF, WinForms, or Blazor Server. |
| `CA2213` | Roslyn / CA | Disposable fields should be disposed | `SemaphoreSlim` and `RandomNumberGenerator` wrap no unmanaged resources; the GC reclaims them safely. The owning class lifetime is tied to the application lifetime, so explicit disposal provides no benefit. | Low | The field holds no unmanaged resources and its lifetime matches the container. Not safe for fields wrapping native handles or file descriptors. |
| `CS1591` | C# compiler | Missing XML comment for publicly visible type or member | Internal and test members are excluded from documentation generation. The suppression prevents noise on non-documented members. | Low | Applied to non-public members or test classes. Do not suppress on public API surface without providing documentation. |
| `EF1001` | Entity Framework Core | Internal EF Core API usage | `IDesignTimeServices` implementations must hook into EF Core internals to register provider-agnostic migration and scaffolding tooling. No public API is involved. | Medium | Restricted to `IDesignTimeServices` implementations only. Review after each EF Core major version bump — internal APIs may change without notice. |
| `IDE0003` | Roslyn / IDE | Remove qualification | The team style prefers explicit `this.` qualification for field access to distinguish fields from locals at a glance. This rule conflicts with that convention. | Designer choice | Always — deliberate style choice. |
| `IDE0011` | Roslyn / IDE | Add braces | The project uses braces on the same line for all blocks; single-line bodies without braces are used selectively where they improve readability. Suppressed globally to match the team style guide. | Designer choice | Always. |
| `IDE0022` | Roslyn / IDE | Use block body for method | Expression-bodied members are used selectively. The rule is suppressed to avoid forcing expression bodies on methods where a block body is clearer. | Designer choice | Always. |
| `IDE0031` | Roslyn / IDE | Use null propagation | Suppressed in cases where the null-propagation form would reduce readability or hide null-check intent. | Designer choice | Always. |
| `IDE0290` | Roslyn / IDE | Use primary constructor | The project uses traditional constructors for explicit `ILogger<T>` injection per coding standards. Primary constructors are reserved for generated or record types. | Designer choice | Always. |
